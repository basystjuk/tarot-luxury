# CODE_STANDARDS — код (Next.js 16 / TypeScript)
`v1.0 · 2026-07-06 · owner: Claude(CTO)`

## Базове
- **Next.js 16 новіший за тренувальні дані** → перед незнайомим API читати `node_modules/next/dist/docs/` (правило AGENTS.md). Не писати «по памʼяті» деприковані патерни.
- TypeScript strict; типи в `types/`; без `any` у нових файлах (існуючі — не гіршити).
- Server Components за замовчуванням; `'use client'` — лише де потрібен стан/браузер. Секрети й service-role — НІКОЛИ в client-компонентах.
- Стиль — як у сусідніх файлах (нейминг, структура, щільність коментарів).

## Структура (факт — дотримуватись)
`app/[lang]/…` сторінки · `app/api/…` роути · `components/` UI · `lib/<домен>/` логіка (telegram, push, astro, numerology, i18n, supabase, analytics…) · `hooks/` · `contexts/` · `types/`. Нова логіка → у відповідний `lib/<домен>`, не в компонент.

## I18n (залізне)
- Кожен UI-текст → `lib/i18n/translations.ts` у **3 мовах одразу** (uk/ru/en). Хардкод рядка в компоненті = блокер рев'ю.
- Роути — через `[lang]`; нова сторінка автоматично працює трьома мовами.

## Залежності
- Нова npm-залежність = **ADR** (навіщо, альтернативи, вага). Спершу шукай наявне: Radix + CVA + framer-motion + lucide покривають 90% UI-потреб.

## API-роути
- Вхід валідувати; помилки → людяний JSON + правильний статус; таймаути на зовнішні виклики (Groq/TG).
- Адмін-роути (`api/admin/*`) — перевірка прав ОБОВʼЯЗКОВА (наявний патерн; новий роут — той самий guard).
- Cron-роути — перевірка `Authorization: Bearer CRON_SECRET` (наявний патерн).

## Перевірка перед комітом
`npm run lint` чистий · `npm run build` зелений (ловить типи+RSC-помилки) · прев'ю побачено.
