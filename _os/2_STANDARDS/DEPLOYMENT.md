# DEPLOYMENT — деплой (Vercel)
`v1.0 · 2026-07-06 · owner: Claude(CTO)`

## Потік
`git push` → Vercel будує й деплоїть. **Гілка ≠ main → Preview Deployment** (безкоштовний staging — використовувати для всього ризикованого); `main` → Production.

## Послідовність (обовʼязкова)
1. Локально: `npm run lint` + `npm run build` зелені (build ловить типи/RSC).
2. Прев'ю ПОБАЧЕНО: локальний `next dev` або Vercel Preview URL (UI-зміни — кожна сторінка, мобільний, теми).
3. Push → задеплоїлось → **прод-перевірка:** зачеплені сторінки живі, консоль браузера чиста, критичний шлях (тул/форма/кабінет) руками.
4. Зміни БД: міграція застосована ДО коду, який її потребує (спершу міграція → потім деплой коду).
5. Статус у BACKLOG.

## Env
Прод-env — лише через Vercel dashboard (Settings → Environment Variables); нова змінна → додати в `.env.example` (без значення) тим самим PR.

## Crons
`vercel.json`: notifications 04:00 UTC · youtube-sync 01:30 UTC. Новий cron = запис туди + Bearer-guard + рядок тут. Перевірка після деплою: Vercel → Crons → останній запуск успішний.

## Відкат
Зламали прод → Vercel dashboard → Deployments → попередній робочий → «Promote to Production» (миттєво). БД-міграції відкатом НЕ зникають — для них писати компенсуючу міграцію.

## Обмеження
- Немає власного сервера: важкі задачі — у межах serverless-лімітів (таймаути функцій!).
- Груповий деплой БД+код — стежити за порядком (п.4), бо Vercel деплоїть атомарно лише код.
