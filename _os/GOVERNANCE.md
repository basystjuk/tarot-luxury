# GOVERNANCE — як еволюціонує Operating System
`v1.0 · 2026-07-06 · owner: Сергій + Claude(CTO)` · успадковано з GrandKeram OS v1.1 (перевірено експлуатацією)

> Власник ПРОЦЕСУ зміни самої схеми. Робить систему живою й самонавчальною.

## Версіонування
- OS має semver (зараз **v1.0**). Кожен файл `_os/` — шапка `version · last-updated · owner`.
- Історію тримає **git** (GitHub remote вже є). Зміни — окремими комітами з «чому».

## Правило зміни самої OS (антимета-пастка)
Міняти схему/стандарт можна **лише якщо проблема повторилась ≥3 рази АБО минуло ≥14 днів реальної експлуатації**. Виняток: помилку вказав Сергій + Claude підтвердив → правило ОДРАЗУ.

## Mistake → Rule (самонавчання)
```
Помилка → запис у 3_OPERATIONS/RETROSPECTIVE.md → якщо повторилась ≥2× →
   правило (CLAUDE.md) АБО автоперевірка (lint-правило / скрипт / CI)
```

## Амендмент (процедура)
1. Запропонувати + причина. 2. Оцінити вплив (що ламає). 3. Оновити файл-власник + бамп версії + коміт. 4. Рішення з компромісом → ADR.

## Зростання (НЕ плодити документи)
Нове = **ADR · автоперевірка · доповнення наявного файлу**. Новий файл — лише коли домен справді новий → **одразу зареєструвати в роутері CLAUDE.md** (урок GrandKeram: файл поза роутером = двійники й розщеплена історія).

## Coverage Review (кінець кожної фази)
«Чи покривають перевірки УСІ класи ризику?» Матриця: Ризик · Покриття · Impact · Cost · Decision. Кожен пробіл → РІШЕННЯ (зараз / план / прийнятий ризик +тригер / N-A).

## Формат аудиту (пропорційний)
**Issue · Severity · Evidence · Confidence (факт/гіпотеза) · Decision · Need-approval.** Аудит без Decision — незавершений. Категоричний висновок без відтворення → «гіпотеза».

## Уроки-передумови (імпорт із GrandKeram, щоб не платити двічі)
- Док ≠ реальність дрейфують за днями → закрив задачу = торкни стандарт.
- «Написано» ≠ «працює» — доки теж підлягають перевірці.
- Пожежний виняток: витік даних / активна атака / компрометація секрету = поза чергою пріоритетів.
